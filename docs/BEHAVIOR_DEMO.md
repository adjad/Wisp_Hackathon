# Behavior demo: Wisp learns your routines and acts before you ask

**Everything shown in this demo is fictional.** Aria Solano, her company
Cedarloop, and every contact, meeting, reminder, note and message are made up.
The data comes from `service/behavior/persona.py` and
`service/demo/founder-demo.json`. Every seeded item lives in a container named
**Wisp Demo** and carries a `[wisp-demo-id:…]` marker. Cleanup removes all of
it.

Wisp learns Aria's routines from her calendar and message rhythm. It predicts
tomorrow and pushes a few useful **nudges** before she asks. Code finds the
patterns as plain statistics, with evidence counts. The model only writes the
sentences.

## What is real and what is fictional

| Item | Where it lives | Fictional? |
| --- | --- | --- |
| Persona history: about 8 weeks of gym, focus blocks, meetings, Dev and Mom messages | Inside Wisp, generated by `generate_persona` | Yes |
| Calendar events, about 200 (past and next 2 weeks) | Your Mac's Calendar, calendar **Wisp Demo** | Yes |
| Reminders, about 13 | Your Mac's Reminders, list **Wisp Demo** | Yes |
| Notes, about 10 | Your Mac's Notes, folder **Wisp Demo** in the default account | Yes |
| Message history with Dev Malik and Mom | Synthetic. Only inside Wisp. Nothing is written to Messages | Yes |
| Auto reminders and tentative holds created by nudges | Wisp's own schedule. Never Apple Calendar or Reminders | Demo output |
| Your own calendars, reminders, notes and messages | Untouched. Synthetic-only mode never reads them for learning | Real, ignored |

## Setup (start at least 30 minutes before 1 PM)

1. **Quit Wisp**: menu-bar icon, then Quit.
2. **Seed the persona** into the Mac's apps. Use the system Python. No
   virtualenv is needed.

   ```sh
   python3 demo/seed_mac_persona.py seed --dry-run | tail -3   # preview counts, writes nothing
   python3 demo/seed_mac_persona.py seed                       # Calendar + Reminders + Notes
   ```

   On the first run, macOS asks you to let Terminal control Calendar,
   Reminders and Notes. Allow all three. Seeding takes a minute or two and
   sends about 50 items per `osascript` call. Rerunning is safe because items
   that already exist are skipped. Times use the Mac's own time zone.
   If Calendar won't create the calendar, create a calendar named
   `Wisp Demo` in Calendar.app, then rerun.

   You can also run `.venv/bin/python demo/wisp_demo.py persona seed`.
3. **Launch Wisp with behavior learning turned on.**
   - **Founder / Intel demo build** (`WISP_FOUNDER_DEMO`): open the app
     normally. Behavior learning and synthetic-only mode turn on
     automatically.
   - **Any other build:**

     ```sh
     WISP_BEHAVIOR=1 WISP_BEHAVIOR_SYNTHETIC_ONLY=1 \
       /path/to/Wisp.app/Contents/MacOS/Wisp
     ```

     Keep that Terminal window open. `WISP_BEHAVIOR_SYNTHETIC_ONLY=1` makes
     Wisp learn only from the persona and the **Wisp Demo** calendar. It never
     learns from your real Messages, Reminders, Notes or questions you ask.
4. **Notifications.** Go to System Settings > Notifications > Wisp. Turn
   notifications on and set the style to **Alerts**, so the buttons stay on
   screen. Turn off Focus / Do Not Disturb.
5. **Warm up** from a second terminal with the repo venv:

   ```sh
   .venv/bin/python demo/wisp_demo.py behavior status     # enabled, observation counts
   .venv/bin/python demo/wisp_demo.py behavior run        # ingest + mine + nudge now
   .venv/bin/python demo/wisp_demo.py behavior patterns   # what it learned (with ids)
   .venv/bin/python demo/wisp_demo.py behavior predict    # tomorrow
   .venv/bin/python demo/wisp_demo.py behavior profile    # the always-on "who you are" card
   ```

   The persona contains these planted routines. Check that `patterns` finds
   them:
   - **Morning lift**, Mon/Wed/Fri 6:45–7:45, about 85% of weeks
   - **Focus block**, weekdays 9:00–11:00
   - **Messages with Dev Malik** on weekday afternoons, plus a Thursday 3 PM 1:1
   - **Calls with Mom** on Sunday evenings
   - On Tue/Thu afternoons she has 3–4 back-to-back meetings and cancels the
     **last one** about 60% of the time
   - When a meeting is booked over the gym, she moves it 4 times out of 5

   The seeded upcoming two weeks already contain a meeting over the next gym
   morning and a back-to-back run on the next Tue/Thu. Nudges can therefore
   fire during warm-up. That is fine. The `drop` presets below create fresh
   triggers on cue.
6. Open the Wisp panel once to confirm it's healthy. Clear the conversation
   with **New chat**.

## Demo beats

Type each prompt exactly into the Wisp panel.

### 1. "What do you know about me?"

Expected: a short profile. Aria lifts Mon/Wed/Fri mornings and protects
9–11 for focus. She talks to Dev in the afternoons and calls Mom on Sundays.
She tends to drop the last of a long run of meetings. The answer includes
evidence ("20 of the last 24 Mondays…").

*Talking point (personal context):* Aria didn't fill in a profile. Wisp
learned it from what her Mac already shows about her week. If a pattern is
wrong, she can reject it, and it stops driving predictions and nudges:
`.venv/bin/python demo/wisp_demo.py behavior patterns --reject <id>`.

### 2. "What will tomorrow look like?"

Expected: tomorrow's likely shape. This covers the gym (if it's a gym day),
the focus block, any meeting at risk of being cancelled, and when Dev is
likely to reach out. Each item comes with a probability and a reason.

### 3. "When do I usually work out?"

Expected: "Mon/Wed/Fri around 6:45–7:45," with how consistent it is.

### 4. "Which meetings do I usually cancel?"

Expected: the last meeting of a 3+ back-to-back run on Tue/Thu afternoons,
about 60% of the time. Meetings booked over the gym usually get moved.

### 5. Gym conflict: Wisp acts on its own, with Undo

```sh
.venv/bin/python demo/wisp_demo.py drop --preset gym-conflict
```

This books the fictional "Foundry export check-in" for 7:00–7:45 on the next
gym morning (tomorrow if tomorrow is Mon/Wed/Fri) in the **Wisp Demo**
calendar, then runs the engine.

Expected: a notification about a meeting over Aria's gym time. The subtitle
reads **"Already done: … · Undo available"**. Wisp has already added a
reminder to Wisp's own schedule. Click **Undo**: the reminder is removed and
Wisp confirms. The same card appears at the top of the Wisp panel.

If no nudge appears within about a minute, Wisp may not have re-read Calendar
yet. It re-reads every few minutes. Run `behavior run` again.

*Talking point (proactive, safe):* Wisp only acts on its own when the action
is reversible and stays on Wisp's own schedule. Undo is always one click away.
It never edits Apple Calendar or Reminders by itself.

### 6. Back-to-back: "Likely skip" plus a drafted note that isn't sent

```sh
.venv/bin/python demo/wisp_demo.py drop --preset backtoback
```

This adds four fictional meetings tomorrow, 14:00–16:00, back to back.

Expected: a nudge that the last one is likely to be skipped. A **"Likely
skip"** tentative hold is placed (Undo available). There is also a **"Draft
reschedule note"** button (the notification's **Do it** button). Click it: the
Wisp panel opens with a reschedule request **prefilled in the composer and not
sent**. Review it and press Return only if you want. Anything that would send
still goes through Wisp's normal confirmation card.

*Talking point:* Wisp never sends a message or changes a real meeting from a
nudge. It drafts, and the user decides.

### 7. Dev's afternoon window

```sh
.venv/bin/python demo/wisp_demo.py drop --preset dev
```

This adds nothing to the Mac. It runs the engine and prints Dev's predicted
contact window. On a weekday afternoon, a **contact window** nudge can fire,
for example: Dev usually replies around now, so it's a good moment to ask
about the tenant-isolation sign-off. Outside that window, show the printed
prediction instead.

### 8. Teaching it

Click **Not now** or **Wrong** on a nudge. Two of those in a week mute that
kind of nudge for 7 days. **Useful** raises its priority. Nudges have a daily
budget of about 4 and stay quiet from 22:00 to 07:00.

## Talking points

- **Proactive.** Wisp doesn't wait for a question. It notices the gym clash
  and the meeting that's likely to be skipped, then acts or offers to.
- **Personal context.** The answers come from Aria's own routine, with
  evidence. They aren't generic advice. She can confirm or reject what it
  learned.
- **Privacy.** In this demo the behavior engine runs **on the Mac** as a
  local SQLite database (`~/.moe/behavior.db`). Code finds the patterns. For
  real Messages, Wisp only records direction, contact and time, never the
  text. The GX10 only phrases the short sentences and runs chat inference.
  It receives the few facts needed to phrase a sentence, not the timeline.
  An optional remote-brain mode can also run the learning on your own GX10.
- **Honest scope.** Today's data is fictional and clearly labeled. With the
  flags removed, the same engine learns from your own Calendar, Reminders
  and message metadata.

## If something doesn't fire

- `behavior status` shows whether learning is on (`enabled`) and how many
  observations it has.
- `behavior run` forces ingest, mining and nudging now. Nudges dedupe by id,
  so re-dropping the same preset on the same day won't re-fire. Use the other
  preset, or show the card already on screen.
- Muted by earlier feedback? Run `behavior nudges --feedback <id> useful`, or
  reset as described under Cleanup.
- No notification? Check the Wisp notification permission and Focus. The
  card at the top of the Wisp panel still shows the nudge.
- To preview the AppleScript a drop or seed would run, add `--dry-run`. It
  works on any OS and writes nothing.

## Cleanup

1. **Quit Wisp first.** If Wisp is still learning when the **Wisp Demo**
   calendar disappears, it would record every upcoming demo meeting as
   "cancelled".
2. Remove the seeded data. This deletes only the containers named
   **Wisp Demo**: the calendar, the Reminders list, and the Notes folder in
   every account.

   ```sh
   python3 demo/seed_mac_persona.py remove          # shows counts, asks before deleting
   ```

   Notes moves deleted notes to **Recently Deleted**. Empty that folder if
   you want them gone right away.
3. Forget what Wisp learned. Use your `WISP_HOME` instead of `~/.moe` if you
   set one.

   ```sh
   rm -f ~/.moe/behavior.db ~/.moe/behavior.db-wal ~/.moe/behavior.db-shm
   ```

   Auto-added reminders and holds on Wisp's own schedule can be undone from
   their nudge (`behavior nudges --undo <id>`). Otherwise they pass with
   their time.
4. Relaunch Wisp normally, without `WISP_BEHAVIOR`. Behavior learning is off
   by default except in the founder demo build.
